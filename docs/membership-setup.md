# Membership activation

The member login UI is available at /login. /account requires a signed LINE, Google, or Facebook session. Admin CMS login is separate at /admin/login and requires ADMIN_USERNAME, ADMIN_PASSWORD_HASH, and ADMIN_SESSION_SECRET. No administrator is granted automatically. There is no persistent member database or member-management API yet.

1. Create a LINE Login web channel and publish it when ready. Set LINE_CHANNEL_ID and LINE_CHANNEL_SECRET in Vercel's server environment variables.
2. Generate AUTH_SECRET with `openssl rand -hex 32` and store it only in Vercel environment variables. Never use a NEXT_PUBLIC prefix for secrets.
3. Register `https://valleys-darley.vercel.app/api/auth/line/callback` as a LINE callback. Set NEXT_PUBLIC_SITE_URL if the storefront domain changes, and register its callback too.
   - For Google, create a Web OAuth client in Google Cloud and register `https://valleys-darley.vercel.app/api/auth/google/callback` as an authorized redirect URI. Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` on the server.
   - For Facebook, create a Meta app with Facebook Login for Web, register `https://valleys-darley.vercel.app/api/auth/facebook/callback` as a valid OAuth redirect URI, and configure its app domain and privacy-policy details for public use. Set `FACEBOOK_APP_ID` and `FACEBOOK_APP_SECRET` on the server. Users outside app roles cannot sign in until the Meta app is live and any required review is complete.
4. For admin CMS access, run `node scripts/generate-admin-credentials.mjs` and set ADMIN_USERNAME, ADMIN_PASSWORD_HASH, and ADMIN_SESSION_SECRET in Vercel. LINE user IDs do not grant admin access.
5. After choosing and registering the actual domain, add its admin subdomain to the existing Vercel project's Domains settings. Use the DNS record Vercel provides, wait for verification and TLS, then set ADMIN_ORIGIN to the full HTTPS origin. The admin domain does not need a LINE callback.
6. Redeploy. Test member login, cancellation, and logout separately from admin login and logout. Member access alone must not grant /admin access. Cookies are host-only: each host logs in independently.

LINE and Google use authorization code + PKCE, state, nonce, server-side identity verification, and signed HttpOnly cookies (24-hour session). Facebook uses authorization code + state, then validates the access token and app/user identity with Graph API. No provider access token is saved in the browser. Admin login uses a separate scrypt password hash and signed HttpOnly cookie (12-hour session). Changing the admin password hash or session secret revokes existing admin sessions.

Each provider button stays disabled until that provider's credentials and `AUTH_SECRET` exist. A first social sign-in creates a session automatically; no password registration is required. Orders are keyed by provider-specific account ID, not an unverified email. Signing in via Google/Facebook does not automatically show orders previously placed via LINE; explicit account linking would need a separate verified flow. Until admin credentials exist the admin login button remains disabled. Do not claim live social login or a custom domain is active until configured and verified.
